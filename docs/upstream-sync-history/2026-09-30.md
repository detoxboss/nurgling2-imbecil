## Schema-15 compatibility bridge

This fork's migration 13 (`stack_sizes`) and upstream's migration 13 (`quest_shares`)/14 (`timers`)
are two incompatible schema lineages that independently claimed the same version numbers.
`MigrationManager.runMigrations()` only runs a migration whose version is strictly above the
database's recorded one, so a database already stamped 13 by a released fork client would skip
upstream's migration 13 forever.

Resolved with a new **migration 15**, reached from either lineage:

```
13 = upstream quest_shares   (unchanged DDL)
14 = upstream timers         (unchanged DDL)
15 = compatibility bridge: ensure quest_shares, ensure timers, ensure+seed-or-reconcile stack_sizes
CLIENT_MAX_SCHEMA_VERSION = 15
```

Every DDL step is factored into a shared helper (`createQuestSharesTable`/`createTimersTable`/
`createStackSizesTable`) so migrations 13/14/15 cannot drift apart. Migration 15 has **no per-step
try/catch** — a `SQLException` anywhere inside it propagates to `runMigrations()`, which rolls back,
does not record version 15, reports it in the skipped map, lets the client initialise against
whichever optional tables already exist, and retries on the next start. (A per-step try/catch design
was considered and rejected during review: it could record version 15 while a structure was still
missing, permanently burying it, and could leave a PostgreSQL connection in an aborted-transaction
state.)

When `stack_sizes` already exists, migration 15 additionally reconciles its live `provenance='seed'`
rows against the current static table (never touching `manual`/`learned` rows or tombstones),
incrementing `version` on every change so the correction propagates to other clients sharing the
database. Full design, the manual/learned precedence rules, and the future-release obligation this
creates: `docs/inventory-grid-system.md` §3.

**Rollout note:** once any merged client raises a shared database to schema 15, released fork clients
(max 13) and released upstream clients (max 14) will both correctly refuse to sync it
(`SchemaTooNewException`). Everyone sharing a database must upgrade together; back it up first.

## Tree-seed selection correction

`VSpec.getSeedForTree()` previously returned `products.get(products.size() - 1)` — wrong for ~24
species (Beech, Poplar, Teabush, and every "Yesteryear's" seasonal-pair species). Upstream's own fix
in this range changed it to `products.get(0)`, which fixed those but broke 14 others whose first
product is a bough/branch/leaf (Alder, Conker Tree, Elm, Fig Tree, Fir, Gray Alder, Laurel, Linden,
Maple, Mulberry, Olive, Spruce, Sweetgum, Yew). Replaced both positional heuristics with semantic
selection: the first non-seasonal product that is not a bough/branch, leaf, or bark. Verified against
all 109 plantable `gfx/terobjs/{trees,bushes}/*` entries in the merged `VSpec.object` (80 non-`*log`
trees + 29 bushes — the 79 `*log` felled-timber mappings under `trees/` are deliberately excluded,
as are the 59 `bumlings/*` rock/ore mappings, neither of which `getSeedForTree` is ever called on):
exactly one valid survivor per entry, pinned with `assertEquals(109, checked)` so a future VSpec
addition or removal is caught rather than silently absorbed.

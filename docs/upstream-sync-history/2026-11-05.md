## Fork changes made in this merge

- **WorldExplorer / Shore Tracer split (approved architectural decision — see conversation record).**
  Upstream's Ocean Explorer rewrite and the fork's pre-existing shore-tracing algorithm are both kept,
  as independent bots: upstream's rewrite retains the native `worldexplorer` id/class/identity
  unmodified; the fork's algorithm (full detail: `docs/world-explorer-system.md`) moved to a new
  identity — `shoretracer`/`ShoreTracer`/`NShoreTracerProp`/`ShoreTracerWnd`/`ShoreTracerFrontier`/
  `ShoreTracerMove`, registered as its own `BotDescriptor`. A one-time migration in `NConfig.read()`
  carries forward any pre-split saved Shore Tracer settings from the legacy `worldexplorerprop` key.
  Full rationale, minimum hooks, and verify steps: `docs/fork-customization-ledger.md`'s "WorldExplorer
  / Shore Tracer split" entry. `SyncRegistryInventoryTest`/`NConfigSyncKeysTest` updated for the new
  bot/key counts (207→208 live bots, 317→323 config keys: +1 fork `shoretracerprop`, +5 upstream
  `mapClaimsShown`/`showThingwallLinks`/`botFavourites`/`disableEasterEggs`/`easterEggSeen`).
- **Semantic-dependency break repaired:** `WaitLpProductDiscovered.java` (fork-only, never touched by
  upstream, shares no file path with the Discovery Atlas rewrite) called
  `NCharacterInfo.IsLpExplorerContains(gobResName, product)` /
  `.IsLpExplorerContainsAnywhere(product)`, both removed by upstream's Discovery Atlas rewrite.
  Repointed to `info.ledger().isDone(product)`, matching the pattern `LpExplorer.java` (upstream-touched,
  merged clean) already uses — the new ledger has no per-resource attribution, so the
  `gobResName`-scoped branch was dropped rather than preserved as dead code.
- **`NConfigSyncKeysTest`/`SyncRegistryInventoryTest` counts and assertions updated** (see above).
- **Ledger correction:** `fork-customization-ledger.md`'s "Fork `BotRegistry` registrations" entry's
  claim that button position follows `bots`-list order was stale even before this sync's World
  Explorer work — upstream's bot-menu redesign sorts each folder's buttons alphabetically by display
  name within named sub-groups. Corrected in place.
- **`NDebugLog`'s log-file prefix** (`"worldexplorer-debug"` → `"shoretracer-debug"`) and all in-code
  log-message tags renamed to `ShoreTracer`/`ShoreTracerFrontier`/`ShoreTracerMove`, consistent with
  the split — `NDebugLog` is exclusively used by the Shore Tracer family; upstream's Ocean Explorer
  does not use it.
- **Post-review correction (found during independent PR review): KNOWN vs. DISCOVERED false-positive
  in `WaitLpProductDiscovered`.** `DiscoveryLedger.isDone(name)` is true for KNOWN/LEGACY/MANUAL as
  well as DISCOVERED, but only DISCOVERED means an LP rise was actually paired with *this* harvest.
  `WaitLpProductDiscovered.check()` originally treated any `isDone()==true` as a confirmed discovery,
  which would let `LpAssistantBot` credit itself with a fresh discovery for a product that was
  already known/legacy-imported/manually-marked, with zero new LP gained this harvest. Fixed by
  querying `ledger().get(product)` and classifying `Outcome.{EXP,DISCOVERED,KNOWN,NONE}`; added
  `isNewLpDiscovery()` as the narrow check callers must use to credit a discovery, while `confirmed()`
  keeps its original broader meaning ("resolved, stop retrying"). `WaitLpFirstProduct`'s `Signal.
  DISCOVERY` and `LpAssistantBot`'s discovered-count increment both now gate on `isNewLpDiscovery()`,
  not `confirmed()`. Regression tests: `test/nurgling/tasks/WaitLpProductDiscoveredTest.java`. The
  30s-unresolved-name-vs-8s-timeout latency question was investigated and documented in
  `WaitLpProductDiscovered`'s class doc, not changed — no concrete evidence of an actual failure, and
  widening timeouts is a separate timing-policy decision. Touched only
  `WaitLpProductDiscovered.java`/`WaitLpFirstProduct.java`/`LpAssistantBot.java`/
  `docs/lp-assistant-bot.md` plus the new test — no Discovery Atlas file
  (`DiscoveryLedger`/`DiscoveryCorrelator`/`DiscoveryTracker`/`NGItem`/`NCore`) was modified.
